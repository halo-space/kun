# Proposal: 将 AI 选择器升级为正式功能

## 目标

将当前标记为"实验性"的 AI 选择器功能升级为正式稳定功能，提供生产级别的可靠性和用户体验。

## 背景

AI 选择器目前被标记为实验性功能，主要原因：
- 缺少重试机制和错误恢复
- 错误处理不够完善
- 缺少超时配置
- 测试覆盖不足
- 文档标注为实验性

## 价值

- 提升用户信心，让用户放心在生产环境使用
- 提供更可靠的 AI 内容提取能力
- 减少因网络问题导致的失败
- 更好的错误提示和调试体验

## 范围

### 包含
- 添加重试机制（指数退避）
- 完善错误处理和自定义错误类型
- 添加超时配置
- 增加单元测试
- 更新文档移除实验性标签

### 不包含
- 支持其他 AI 提供商（如 Claude、Gemini）
- 缓存机制
- 批量请求优化

## 风险

- 向后兼容性：需要保持现有 API 不变
- 性能影响：重试机制可能增加延迟
- 依赖稳定性：仍依赖外部 OpenAI API

## 成功标准

- 所有新增代码有单元测试覆盖
- 文档更新完成
- 示例代码可正常运行
- 向后兼容现有用户代码
